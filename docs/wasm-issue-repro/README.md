# Минимальный публичный repro (не воспроизводит)

Три крошечных проекта без нашего кода: C#-хост → F#-библиотека `Core` → F#-библиотека `Algebra`
(в `Algebra` — модульные `let` и функция, читающая эти значения через `<StartupCode$Algebra>.$Algebra`).

```
dotnet run -c Release --project Host
```

**Результат: `22` — ошибки нет.** Дефект на таком размере не воспроизводится ни в Release, ни (проверено
отдельно) в WASM-сборке с C#-хостом: маленькая F#-библиотека с модульными значениями спокойно грузится
через границу сборок.

## Что в нашем проекте иначе

- `Algebra` — ~23 файла (рациональная арифметика, многочлены, факторизация, базисы Грёбнера), `Core` — ~40 файлов;
  в обоих десятки модулей с модульными значениями и таблицами.
- `Core` читает из `Algebra` не только функции, но и **модульные значения-таблицы** (`StepLog`, `StepDict`,
  реестры алгоритмов), часть из них — через обобщённые/структурные типы.
- Много `System.Numerics.BigInteger` и обход раскладки через `Unsafe.As` на зеркальную структуру.
- Ошибка видна в **Release**-сборке (и на десктопе, и в WASM): настольный Release — 344 провала из 1985,
  WASM до перехода на одну сборку — 5 задач из 10; в Debug всё зелёное.
- Плоская сборка (`Cas.Algebra` + `Lisp.Core` в одну) убирает ошибку в обоих случаях.

## Что это значит для issue

Публичного минимального воспроизведения пока нет: уменьшать надо от реального `Core`/`Algebra`, а не наращивать
синтетику. В черновике issue (`docs/wasm-issue-dotnet-runtime.md`) это записано прямо, чтобы мейнтейнеры не
искали repro там, где его нет.
