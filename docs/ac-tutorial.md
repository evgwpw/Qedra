# AC-сопоставление на пальцах

Короткий туториал: что это, зачем и как пользоваться. Подробности — [`lisp-library-guide.md`](lisp-library-guide.md) (раздел `match`).

## 1. Что такое «сопоставление с образцом»

Образец — это выражение с «дырками» (переменными образца, имена начинаются с `?`). Сопоставить образец с выражением — найти, что подставить в дырки, чтобы получилось выражение.

```
образец:    (sin ?u)
выражение:  (sin (* 2 x))
ответ:      ?u = (* 2 x)
```

Это основа правил переписывания: «если видишь `sin(?u)^2 + cos(?u)^2`, замени на 1», таблиц интегралов («`∫ exp(?u) d?u` = `exp(?u)`»), а в будущем — поиска применимых теорем (шаг M).

## 2. В чём проблема без AC

Обычное (структурное) сопоставление сравнивает «буква в букву». Но у `+` и `*` порядок и группировка не важны:

- `x + y` = `y + x` — коммутативность (**C**);
- `(x + y) + z` = `x + (y + z)` = `x + y + z` — ассоциативность (**A**).

Поэтому структурно не ловятся очевидные вещи:

| образец | выражение | структурно | по смыслу |
|---|---|---|---|
| `(* ?c x)` | `(* x 3)` | нет (порядок) | да, c = 3 |
| `sin²?u + cos²?u` | `3 + sin²x + y + cos²x` | нет (лишние слагаемые, порядок) | да, u = x |
| `(* ?a ?b)` | `(* 2 x y)` | нет (три множителя) | да, если разрешить «остаток» |

Раньше это обходили вручную: правила писали по два раза (в обоих порядках), интегратор перебирал перестановки, F#-упрощатель обрабатывал sin²+cos² отдельным кодом.

**AC-сопоставление** = сопоставление с учётом ассоциативности и коммутативности: аргументы `+` и `*` рассматриваются как мешок (мультимножество), а не как упорядоченный список.

## 3. Два вида переменных

- **Обычная `?x`** — ровно один аргумент суммы/произведения (или любое подвыражение вне `+`/`*`).
- **Сегментная `?r...`** (три точки в имени) — «всё остальное»: сколько угодно аргументов, в том числе ни одного. Пустая в `+` даёт 0, в `*` — 1.

```lisp
(ac-match '(* ?a ?b ?r...) '(* 2 x y))
;; ⇒ ((?a 2) (?b x) (?r... y))       ; первое решение

(ac-match-all '(* ?a ?b ?r...) '(* 2 x y))
;; ⇒ 6 решений: (?a,?b) — любая упорядоченная пара из {2, x, y}, остаток — третий

(ac-match '(+ (^ (sin ?u) 2) (^ (cos ?u) 2) ?r...) '(+ 1 y (^ (sin x) 2) (^ (cos x) 2)))
;; ⇒ ((?u x) (?r... (+ 1 y)))       ; тождество найдено внутри большой суммы

(ac-match '(* ?a ?b) '(* 2 x y))
;; ⇒ #f   ; две обычные переменные не могут забрать три множителя — нужен ?r...
```

Внутри других функций (`sin`, `^`, `=`…) аргументы сопоставляются по позициям, но внутри каждого аргумента снова работает AC.

## 4. Обратная подстановка

`(ac-subst образец привязки)` — подставить найденное обратно (с упрощением). Инвариант, который проверяют тесты: подстановка решения в образец даёт исходное выражение.

```lisp
(ac-subst '(* ?a ?b ?r...) '((?a 2) (?b x) (?r... y)))   ;; ⇒ (* 2 x y)
```

## 5. Единицы (флаг `:identities`)

Иногда выражение «короче» образца, но совпадает «с единицей»: `x` = `1·x` = `x + 0` = `x^1`. По умолчанию это выключено (иначе слишком много ложных совпадений); включается флагом:

```lisp
(ac-match '(* ?a x) 'x :identities #t)           ;; ⇒ ((?a 1))
(ac-match '(+ x ?b) 'x :identities #t)           ;; ⇒ ((?b 0))
(ac-match '(* ?a (^ x ?n)) 'x :identities #t)    ;; ⇒ ((?a 1) (?n 1))
```

Зачем: правило таблицы «∫ a·x^n dx» должно ловить и просто `x` (a = 1, n = 1).

## 6. Условия (`:where`)

Образец часто слишком «всеядный». `(* ?c ?x)` против `3·x` даёт два решения: c = 3, x = x и c = x, x = 3. Для правила линейности интеграла (∫ c·f dx = c·∫ f dx) нужно, чтобы c **не зависел от x**:

```lisp
(ac-match '(* ?c ?f) '(* 3 x) :where '(x-free? ?c 'x))
;; ⇒ ((?c 3) (?f x))          ; вариант c = x отброшен: x содержит x
```

Условие проверяется на каждом кандидате, поэтому возвращается первое **подходящее** решение. Условие видит декларации (`declare`, `assuming`):

```lisp
(ac-match '(^ ?b ?n) '(^ y k) :where '(integer-valued? ?n))
;; без деклараций: про k неизвестно, целое ли оно ⇒ #f, и записан вопрос (см. ниже)
;; (assuming ((k integers)) ...) ⇒ ((?b y) (?n k))
```

## 7. «Неизвестно» — это вопрос, а не провал

Условия трёхзначные: «да», «нет», «неизвестно» (например, `positive?` для символа без деклараций). Решение принимается только при «да». Но кандидат с «неизвестно» не теряется молча — записывается условие:

```
(ac-where-unknown (positive? k))   — «правило подошло бы, если k > 0»
```

Это видно в `conditions` ответа (MCP, `--json`). Для шага M (теоремы mathlib4) это и есть механизм «гипотеза теоремы → вопрос пользователю» (как в примере с фенитоином: «теорема применима, если K < 1 — это так?»).

Аналогично при превышении лимита перебора (по умолчанию 10 000 попыток) возвращается `#f` и пишется `(ac-match-limit n)` — это «не знаю», а не «не совпало».

## 8. Где это будет использоваться

| подшаг | что даёт |
|---|---|
| AC.3 ✅ | правила упрощателя `defrule … :ac`: одно правило вместо двух-трёх вариантов, тождества внутри больших сумм; шаги `simplify` показывают правило и привязки (см. ниже) |
| AC.4 ✅ | вторая попытка табличного интегрирования на AC: строки с суммой параметров `?c...`, коэффициентом `?k` (единица — `:identities`) и условиями `x-free?` (см. ниже) |
| AC.5 ✅ | поиск образца в подвыражениях (`ac-match-sub`, `ac-replace-sub`) и построение образца из DAG фактов mathlib (`pattern-from-dag`) — основа применения теорем в шаге M (см. ниже) |

**AC.3 — что сделано.** Правило с флагом `:ac` сопоставляется через `ac-match` (остальные — как раньше):

```lisp
(defrule pythagorean-common-factor
  (+ (* ?c... (^ (sin ?u) 2)) (* ?c... (^ (cos ?u) 2)) ?r...)
  (+ ?c... ?r...) :ac
  :title "Основное тригонометрическое тождество (общий множитель)")
```

(`:title` — необязательный заголовок шага; без него шаг называется «правило имя».)

Раньше `z sin²x + z cos²x + y` не сворачивалось: F#-упрощатель умеет это только с числовым общим множителем
(`2 sin²x + 2 cos²x` — он же, шаг `simplify:pythagorean`, правило не вмешивается). Теперь — по правилу, в любой
сумме, с любым общим множителем (`?c...` — пустой остаток означает 1). Реальный вывод:

```
steps(simplify(3 + z*sin(x)^2 + z*cos(x)^2 + y), "full")
1. Упрощение: 3 + z*sin(x)^2 + z*cos(x)^2 + y ⇒ 3 + y + z
   1.1 Основное тригонометрическое тождество (общий множитель): 3 + y + z*cos(x)^2 + z*sin(x)^2 ⇒ z + (3 + y)
       u = x, множитель c = z, остальные слагаемые: 3 + y
```

Привязки поясняются по смыслу узла образца: обычная переменная — `u = x`; сегментная под `*` — «множитель c = z»
(несколько — «множители»), под `+` — «остальные слагаемые: 3 + y», в других местах — «остаток r = …». Тот же вывод
по-английски (`"en"`): `Pythagorean trigonometric identity (common factor)`, `u = x, factor c = z, remaining terms: 3 + y`.

А переведённые на `:ac` правила `lib/rules.lisp` — `sin-integer-pi`, `cos-integer-pi`, `pow-product` — ловят три и
более множителей: `sin(2 n pi)` при целом `n` — `0`, `cos(2 n pi)` — `1`, `(x y z)^(1/2)` при положительных
`x, y, z` — `x^(1/2) y^(1/2) z^(1/2)`; три правила на пары `(* ?a ?b)` в обоих порядках превратились в одно. Подробности
и правила записи — `lisp-library-guide.md`, раздел «`defrule … :ac`».

**AC.4 — что сделано.** Интегратор (`lib/integrate/core.lisp`) после прежней таблицы `int-table-try` (структурное
сопоставление, строки в обоих порядках бинарных `+`/`*`) пробует вторую таблицу `int-ac-table` через `ac-match` с
`:identities #t` и условием `:where`: `?u` линеен по `x`, `(const ?v)` — `x-free?`, `(pos ?v)`, `(not-num ?v k)`. Строка:

```lisp
(int-ac-rule '(^ (+ ?c... (* ?k (^ ?u 2))) -3/2)
             '(* ?u (^ ?c... -1) (^ (+ ?c... (* ?k (^ ?u 2))) -1/2))
             '(const ?c...) '(not-num ?c... 0) '(const ?k) '(not-num ?k 0))
```

`?c...` — вся сумма параметров (`a + b`), `?k` — коэффициент при `u²`: единица берётся флагом `:identities`
(`1 + x²` — `k = 1`, `1 − x²` — `k = −1`), одна строка заменяет четыре. Условие проверяется на каждом кандидате:
`(x² + y²)^(-3/2)` берёт `u = x, c = y²`, а `(sin x + x²)^(-3/2)` не берётся (сумма зависит от `x`). Шаг — тот же `int-table`
с формулой строки и привязками:

```
steps(integrate(1/(a+b+3*x^2)^(3/2), x), "full")
1. Интегрирование по x: ∫ 1/(a + b + 3x^2)^(3/2) dx ⇒ x/((a + b)(a + b + 3x^2)^(1/2))
   1.1 Табличный интеграл: ∫ … ⇒ x/((a + b)(a + b + 3x^2)^(1/2))
       ∫ 1/(c + k*u^2)^(3/2) du = u/(c(c + k*u^2)^(1/2)) (c ≠ 0, k ≠ 0); c = a + b, k = 3
```

Новые интегралы: `(c + k u²)^(-3/2)`, `(c + u²)^(3/2)`, `(c − u²)^(3/2)` (параметры суммой), а в обычную таблицу добавлены
`sech`, `csch`, `csch²`. AC-попытка не меняет прежних ответов: на узле, где прежняя таблица нашла правило, она не вызывается,
а строки (головы `^`) сверяются по голове подынтегрального. Заменять перебор перестановок `int-variants` на AC
не стали: AC покрывает все перестановки (проверено тестом), но обычное сопоставление быстрее.

**AC.5 — что сделано.** Раньше образец сопоставлялся только с выражением целиком. Теперь его можно искать где угодно:

```lisp
(ac-match-sub '(sin ?u) '(+ 1 (sin x) (* 2 (sin y))))
; → (((1) ((?u x))) ((2 1) ((?u y))))      путь — индексы аргументов от корня, с нуля
(ac-match-sub '(+ (sin ?u) (cos ?u)) '(f (+ b (cos y) (sin y) a)))
; → (((0) ((?u y))))                       образец-сумма находится внутри большей суммы
(ac-replace-sub '(+ (^ (sin ?u) 2) (^ (cos ?u) 2)) 1
                '(g (^ (+ q (^ (sin x) 2) (^ (cos x) 2)) 3)))
; → (g (^ (+ 1 q) 3))                      остаток q сохранён, заменён только найденный кусок
```

Сумма `(+ ?a ?b)` обычно занимает лишь часть большей суммы `(+ x y z)`. Поэтому для образца-суммы или -произведения
поиск сам добавляет «хвост» (сегментную переменную) — остаток, который не трогают и пришивают к замене обратно. Если
нужна точность («только целый узел»), пишут `:partial #f`. Замена `simplify`-ит только заменённый узел: остальное
выражение остаётся как было (его канонизирует вызывающий).

**Как это ляжет на шаг M (теоремы mathlib).** Теорема хранится фактами `node`/`arg` (DAG). `pattern-from-dag` обходит DAG от
корня заключения и собирает S-выражение образца: `#var` становится `?v0`, `?v1`, … (номер переменной телескопа), головы
Lean переводятся по таблице (`Eq` → `=`, `Real.sqrt` → `sqrt`, `HPow.hPow` → `^`), бинарные `HAdd.hAdd`/`HMul.hMul`
склеиваются в `+`/`*` с любым числом аргументов. Теорема `Real.sqrt_sq_eq_abs` — `Eq (Real.sqrt (HPow.hPow ?x 2)) (abs ?x)` —
превращается в `(= (sqrt (^ ?v0 2)) (abs ?v0))`; `ac-match-sub` находит её в целевом выражении, `:where` проверяет
гипотезы теоремы (`hyp`: `0 ≤ x` → `'(non-negative? ?v0)`), а неопределённые гипотезы остаются в `conditions` как
`(ac-where-unknown …)` — готовые вопросы пользователю. Применение теоремы к выражению — `ac-replace-sub` с левой частью
как образцом и правой как заменой. Сам импорт фактов и запросы Datalog — шаг M (здесь только функции-«клей»).

## 9. Ограничения

- Общая задача AC-сопоставления NP-полная; спасает лимит перебора и маленькие образцы (на практике ≤ 4 переменных).
- Сегментная переменная — не больше одной на узел `+`/`*`.
- Сегментная может быть пустой, поэтому бывают «вырожденные» решения (`ac-match-all` их тоже вернёт) — отсекаются условиями `:where`.
- Переменная на месте функции (`(?f x)`) не поддерживается.
- Перед сопоставлением выражение НЕ упрощается (`simplify` свернул бы `sin²x + cos²x` в 1 раньше, чем его найдут); делается только лёгкая нормализация (`-`, `/` → `+`, `*`, `^`; вложенные суммы/произведения раскрываются).
- Опции — самовычисляющиеся ключевые слова (`:where`, `:identities`, `:limit`); прежняя запись с кавычкой (`':where`) тоже работает.

## 10. Как это у других

Ближе всего — Mathematica (`Orderless`/`Flat`, `x__`/`x___`, `a_.`, `/;` — наши `+`/`*`, `?r...`, `:identities`, `:where`), Maude (`assoc comm id:`), MatchPy (Python). Частично — другие системы (`Wild(exclude=[x])`), Maxima (`matchdeclare` + `freeof`). Записывать «неизвестно» как вопрос пользователю — насколько известно, особенность нашей системы.
