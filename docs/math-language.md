# Математический язык — руководство пользователя

Входной язык в духе Derive и muSIMP: пишете формулы так, как на бумаге, а система вычисляет и печатает результат в той же записи. Под капотом — Lisp-интерпретатор с библиотекой компьютерной алгебры; язык — тонкая оболочка над ней.

```
math> f(x) := x^2 + sin(x)
f(x) := x^2 + sin(x)
math> integrate(f(x), x)
1/3*x^3 - cos(x)
math> a := 5
5
math> f(a)
25 + sin(5)
math> fact(n) := if(n = 0, 1, n*fact(n - 1))
fact(n) := if(n = 0, 1, n*fact(n - 1))
math> fact(10)
3628800
```

## Запуск

| Команда | Что делает |
|---|---|
| `dotnet run --project src/Lisp.Host -- --math` | интерактивный сеанс в математическом режиме (приглашение `math> `) |
| `dotnet run --project src/Lisp.Host -- файл.mth` | выполнить файл языка и напечатать значение каждого оператора |
| `dotnet run --project src/Lisp.Host` | обычный Lisp-режим (`lisp> `); команда `:math` переключает в математический |
| `Lisp -e "выражение" [...]` | выполнить выражения Lisp, напечатать значение последнего (код 0; ошибка — код 1); несколько `-e` — в одном окружении |
| `Lisp --math -e "2x+1"` | то же во входном языке (печать `mathPrintLang`) |
| `Lisp файл.lisp -e "(f 3)"` | сначала загрузить файл (без печати результата), потом выражения — отладка библиотек без временных файлов |
| `Lisp --help` / `-h` | справка по всем режимам; неизвестный ключ — код 2 |

Печать результата (`-e`, REPL, `show`) ограничена 2000 символами; при превышении — хвост `… [обрезано: N символов, M узлов]`. Лимит меняется из Lisp: `(set-print-limit 100)`, `0` — без ограничения. Builtin `(show e)` печатает `e` в математической записи и возвращает его — удобно вставлять в цепочки при отладке.

Команды сеанса (набираются как есть, без скобок):

| Команда | Действие |
|---|---|
| `:math` / `:lisp` | переключить режим |
| `:debug` | показывать стек Lisp в сообщениях об ошибках (по умолчанию — только сообщение) |
| `exit`, `quit`, `,q` | выход |

Если скобка не закрыта или строка кончается оператором (`a +`, `f(x) :=`), ввод продолжается на следующей строке (приглашение `...> `).

Для программ-агентов есть JSON-интерфейс: `{"op":"math","code":"f(x) := x^2; f(3)"}` (см. ниже «Из других программ»).

## Основы синтаксиса

Программа — последовательность операторов. Операторы разделяются **переводом строки** или **`;`**. Перевод строки внутри незакрытых скобок и после «висячего» оператора (`a +` ⏎ `b`) — продолжение. Комментарий — `//` до конца строки.

```
a := 1; b := 2          // два оператора в строке
c := [1, 2,
      3, 4]             // один оператор на две строки
```

Результат каждого оператора печатается. Ошибка разбора указывает строку и позицию: `math: строка 2, позиция 6: неожиданный токен «)»`.

### Операторы языка

| Запись | Смысл |
|---|---|
| `a := выражение` | присваивание; правая часть вычисляется сразу, значение пересчитывается при каждом использовании имени (см. «Переменные») |
| `a :=` | снять присваивание (то же, что `clear(a)`) |
| `f(x, y) := выражение` | определение функции |
| `f(n, s := 0) := выражение` | определение с локальными переменными (параметры со значением по умолчанию) |
| `v[i] := e`, `m[i, j] := e` | присваивание элементу вектора/матрицы |
| `x :∈ D`, `x :in D` | декларация: «x принадлежит D» (D — домен или интервал) |
| любое выражение | вычисляется и печатается |

### Операции и приоритеты

От самого слабого к самому сильному:

| Уровень | Операции | Примечание |
|---|---|---|
| 1 | `or` | трёхзначная логика |
| 2 | `and` | |
| 3 | `not` | префиксная |
| 4 | `=`  `/=` (или `≠`, `!=`)  `<`  `>`  `<=` (`≤`)  `>=` (`≥`)  `∈` (`in`)  `∉` | отношения, не ассоциативны |
| 5 | `∪` (объединение), `\` (разность множеств) | слева направо |
| 6 | `∩` (пересечение) | |
| 7 | `+`  `-` | |
| 8 | `*`  `/`, неявное умножение (`2x`, `3(x+1)`, `2sin(x)`) | `1/2x` — это `(1/2)·x` |
| 9 | унарный `-`, `+` | `-x^2` = −(x²) |
| 10 | `^` (или `**`) | правоассоциативна: `x^y^2` = x^(y²); `2^-3` допустимо; `**` — то же, что `^` (запись Python и других систем) |
| 11 | постфикс `v[i]`, `m[i, j]`, `n!` | можно подряд: `m[1][2]`, `n!!` |

Следствия: `x + 1 < y*2` читается как `(x+1) < (y*2)`; `a < b and c = d or not e` — как `((a<b) and (c=d)) or (not e)`; `x ∈ {1,2} ∪ {3}` — как `x ∈ ({1,2} ∪ {3})`.

### Литералы и константы

| Запись | Значение |
|---|---|
| `42`, `2.5`, `1e-3`, `1/3` | целое, дробное, рациональное число (`1/3` — точное число, а не деление) |
| `"текст"` | строка (экранирование `\"`, `\\`, `\n`) |
| `true`, `false`, `unknown` | значения трёхзначной логики |
| `π` или `pi` | число π (символ `pi`) |
| `∞` или `inf` | бесконечность; `-∞` — минус бесконечность |
| `e` | число Эйлера: `exp(1)`; пока вы не присвоили `e` своё значение |
| `%i` или `ⅈ` | мнимая единица. **`i` — обычное имя**, не мнимая единица |
| `ℕ ℤ ℚ ℝ ℂ` | домены (то же: `naturals integers rationals reals complexes`) |
| `[a, b, c]` | вектор; `[[1, 2], [3, 4]]` — матрица |
| `{a, b}`, `{}` или `∅` | множество, пустое множество |

Греческие буквы (`α β γ … ω`) превращаются в латинские имена `alpha beta …`.

## Переменные

Имя без значения — просто символ: выражение `x^2 + 1` вычисляется как формула, а не как число.

```
math> a := 5
5
math> a^2 + x
25 + x
math> clear(a)
true
math> a^2 + x
a^2 + x
```

Правила (как в Derive):

* присвоенное имя **подставляется** при вычислении;
* **ленивые переменные.** При присваивании правая часть вычисляется сразу (`n := 5; n := n + 1` даёт 6), но при **использовании** имени его значение вычисляется заново с текущими присваиваниями: `y := x^2; x := 3; y` → `9`, а после `clear(x)` снова `x^2`. Значения хранятся так, как вычислены при присваивании (с неприсвоенными именами внутри); подстановка идёт при каждом обращении;
* **циклическое определение** отвергается при присваивании: `x := x + 1` при неприсвоенном `x`, `a := b; b := a` дают ошибку «циклическое определение x» (а не зависание); цепочки определений глубже 100 — тоже ошибка;
* `clear(a, b)` снимает присваивания и определения функций; `clear()` — все;
* **переменная решения/интегрирования/дифференцирования/предела/разложения должна быть неприсвоенным именем** (`solve`, `integrate`, `diff`, `limit`, `series`, `taylor`, `subst(e, x, v)`). Проверка идёт до вычисления остальных аргументов:

```
math> x := 7
7
math> solve(x^2 - 5x + 6 = 0, x)
ОШИБКА: x имеет значение 7 — переменная решения не должна быть присвоена; снимите присваивание: x :=
math> x :=
x
math> solve(x^2 - 5x + 6 = 0, x)
{2, 3}
```

Параметр функции, равный самому себе (`g(x) := integrate(x^2, x); g(x)`), присвоенным не считается.

Переменные и функции языка живут в отдельном пространстве и **не затирают** функции библиотеки: можно написать `map := 5` или `union := 3` — `{1} ∪ {2}` всё равно работает.

| Функция | Что делает |
|---|---|
| `clear(a, b)` | снять присваивания и определения функций у имён (`clear()` — у всех) |
| `subst(e, x, v)` | подставить v вместо x в выражение e (также `x = v` и `[x = 1, y = 2]`) |

## Функции

```
math> g(x, y) := x*y + 1
g(x, y) := x*y + 1
math> g(3, 4)
13
math> g(a, b)
1 + a*b
```

* Параметры связываются локально на время вызова и **не портят** переменную с тем же именем: после `a := 10; k(a) := a*2; k(3)` значение `a` по-прежнему 10.
* Область видимости лексическая: тело функции видит свои параметры и глобальные переменные, но **не** параметры вызывающей функции.
* Рекурсия работает (`fact`, `fib`).
* Вызов `f(args)`: сначала ищется ваша функция; иначе — функция библиотеки с этим именем (список ниже); иначе результат — **невычисленная форма** `f(args)` с вычисленными аргументами: `foo(1, a + 1)` → `foo(1, 6)` при `a := 5`.
* Функция языка с тем же именем, что и функция библиотеки, имеет приоритет (`det(m) := 42` перекрывает `det`).

### Условия

`if(условие, then, else)` — ленивый: вычисляется только выбранная ветка (рекурсия `fact` поэтому останавливается).

Условие вычисляется в `true`, `false` или `unknown`. Если оно неопределённо, `if` остаётся **невычисленным** (ветки не вычисляются, но значения переменных в них подставляются):

```
math> g(y) := if(y > 0, y, -y)
math> g(-3)
3
math> g(z)
if(z > 0, z, -z)
```

Формы `if`:

| Запись | Смысл |
|---|---|
| `if(c, a, b)` | `a` при истинном `c`, `b` при ложном; при неопределённом — невычисленный `if(...)` |
| `if(c, a)` | без else: при ложном `c` значение **`false`** (в Derive невычисленное — здесь выбрано `false`, чтобы `if(k > n, exit)` в циклах не оставлял мусора); при неопределённом — невычисленный `if(c, a)` |
| `if(c, a, b, u)` | четвёртая ветвь `u` — когда условие неопределённо (`unknown`); вычисляется только выбранная ветвь |

Отношения:

| Выражение | Результат |
|---|---|
| числа | `true`/`false`: `1/2 < 2/3` → `true`, `1 = 1.0` → `true` |
| выражения | разность упрощается до числа → `true`/`false`; иначе остаётся отношением: `x + 1 > x` → `true`, `z < 1` → `z < 1` |
| `=` вне условия | если ответ не определён, остаётся **уравнением** — так `solve(x^2 = 2, x)` получает уравнение |

Знак выражений выводится из деклараций: после `n :∈ ℕ` отношение `n >= 0` даёт `true`.

`and`, `or`, `not` — трёхзначные (по Клини): `z > 0 and false` → `false`, `z > 0 or true` → `true`, `z > 0 and true` → `z > 0`. Операнды `and`/`or` вычисляются слева направо с остановкой на `false`/`true`.

## Векторы и матрицы

Индексы **начинаются с 1** (как в Derive).

Линейная алгебра (`lib\linalg.lisp`, шаги LA.1–LA.3) доступна и из языка для функций с именем из одного слова: `rref(m)`, `nullspace(m)`, `columnspace(m)`, `charpoly(m, l)`, `eigenvalues(m)`, `eigenvectors(m)`, `diagonalize(m)`. Имена с дефисом (`jordan-form`, `mat-exp`, `mat-power`, `diagonalizable?`) в языке пока не переименованы (нет пары в `m-renames`) — их вызывают из Lisp; примеры — `examples\08-linear-algebra.lisp`, справочник — `docs\lisp-library-guide.md` § linalg. Результаты возвращаются списками Lisp (не векторами языка).

```
math> v := [1, 2, 3]
math> v[2]
2
math> m := [[1, 2], [3, 4]]
math> m[2, 1]
3
math> m[1]
[1, 2]
math> m*m
[[7, 10], [15, 22]]
math> det(m)
-2
math> inv(m)
[[-2, 1], [3/2, -1/2]]
```

* Арифметика: `v + w`, `2*v`, `-v`, `v*w` (скалярное произведение), `m*v`, `m*m`.
* Индекс вне границ — ошибка `индекс 9 вне границ 1..3`; символьный индекс (`v[i]`) остаётся невычисленным.
* Пустой вектор `[]` допустим (начальное значение накопителя: `r := []; r := append(r, [5])`); «рваные» матрицы не допускаются.
* Элемент можно присвоить: `v[2] := 20`, `m[1, 2] := 0` (см. «Программирование»).
* Функции: `det`, `inv`, `rank`, `dot`, `cross` (3-векторы), `norm`, `diff([x, x^2], x)` (покомпонентно).

| Функция | Что делает |
|---|---|
| `rref(m)` | приведённая ступенчатая форма матрицы (Гаусс–Жордан) |
| `nullspace(m)` | базис ядра: фундаментальная система решений A·x = 0 |
| `columnspace(m)` | базис пространства столбцов |
| `charpoly(m, l)` | характеристический многочлен det(λI − A) по переменной l |
| `eigenvalues(m)` | собственные значения с кратностями |
| `eigenvectors(m)` | собственные пары (λ, кратность, (v₁ …)) |

## Множества и домены

```
math> s := {1, 2, 3} ∪ {3, 4}
{1, 2, 3, 4}
math> s ∩ {2, 4, 6}
{2, 4}
math> s \ {1}
{2, 3, 4}
math> 2 ∈ s
true
math> 7 ∈ s
false
math> {2, 1} = {1, 2}
true
```

Множества хранятся упорядоченными без повторов; равенство не зависит от порядка. Функциональная запись — в таблице (те же операции есть знаками `∪`, `∩`, `\`, `∈`):

| Функция | Что делает |
|---|---|
| `union(A, B)` | объединение множеств (или `A ∪ B`) |
| `intersection(A, B)` | пересечение (или `A ∩ B`) |
| `set_difference(A, B)` | разность (или `A \ B`) |
| `card(A)` | число элементов конечного множества |
| `power_set(A)` | множество всех подмножеств (булеан) |
| `subset?(A, B)` | `A ⊆ B`: `true`, `false` или `unknown` |

Принадлежность `x ∈ D` — трёхзначная: `true`, `false` или `unknown`.

### Декларации

`x :∈ D` сообщает системе свойства символа (домен ℕ ℤ ℚ ℝ ℂ или интервал `interval(0, ∞)`, `positive`, `nonnegative`, `negative`, `nonpositive`). Они влияют на `solve`, на знак выражений и на `∈`:

```
math> solve(z^2 + 1 = 0, z)
{%i, -%i}
math> z :∈ ℝ
z ∈ ℝ
math> solve(z^2 + 1 = 0, z)
{}
math> undeclare(z)
z
```

Декларации — состояние сессии (действуют и в Lisp-режиме; у каждой сессии `--json`/MCP — свои); `clear(z)` их **не** снимает. Снять декларации имени: `z :∈` (без домена, по аналогии с `z :=`) или `undeclare(z)`; снять все пользовательские: `clear()` (в Lisp — `(math-reset)` или `(reset-declarations)`). `declarations()` (Lisp: `(declarations)`) возвращает текущие декларации списком `(имя домен ...)`; системная декларация `pi > 0` в список не входит и после сброса остаётся. Несколько деклараций одного символа действуют вместе (пересечение).

```
math> z :∈ ℝ
z ∈ ℝ
math> z :∈
z
math> solve(z^2 + 1 = 0, z)
{%i, -%i}
```

### Интервалы

Интервал — подмножество ℝ. Литералы (как в математике):

| запись | интервал |
|---|---|
| `(a, b)` | открытый |
| `[a, b)` | закрыт слева, открыт справа |
| `(a, b]` | открыт слева, закрыт справа |
| `interval(a, b)` | закрытый `[a, b]` |
| `interval(a, b, левая, правая)` | флаги `open`/`closed` у каждого конца |

Бесконечности: `∞`, `-∞` или `inf`, `-inf`; бесконечный конец всегда открыт (`interval(0, ∞, closed, closed)` — это `[0, ∞)`).

Запись `[a, b]` — **вектор**, как и раньше (иначе нельзя было бы написать вектор из двух чисел). Закрытый интервал `[a, b]` понимается только в позиции домена: правая часть `∈` и `:∈`, второй аргумент `in?(x, D)`, аргументы-домены `declare(x, D...)`. Вне этих позиций пишите `interval(a, b)`. Запятая в круглых скобках `(a, b)` раньше была ошибкой, поэтому читается как интервал; скобки без запятой — по-прежнему группировка.

```
math> x :∈ (0, ∞)
x ∈ (0, ∞)
math> solve(x^2 = 4, x)
{2}
math> y :∈ [0, 1]
y ∈ interval(0, 1)
math> 1/2 ∈ [0, 1]
true
math> 2 ∈ (0, 2)
false
```

**Печать однозначна и читается обратно в то же значение** (проверено тестами round-trip): полуоткрытые и открытые печатаются как `[a, b)`, `(a, b]`, `(a, b)`; закрытый — как `interval(a, b)` (запись `[a, b]` читалась бы как вектор); пустой — как `interval(1, 0)` (запись `∅` читалась бы как пустое *множество*). Границы — числа (в том числе `1/2`, `-1.5`) и `∞`/`-∞`. В Lisp-режиме `print` интервала по-прежнему `[0, inf)`.

| Функция | Что делает |
|---|---|
| `declare(x, D, ...)` | объявить свойства символа (домен или интервал) — то же, что `x :∈ D` |

## Программирование

Элементы программирования — как в Derive 6: блоки `prog`, циклы `loop`/`exit`, `return`, локальные переменные, присваивание элементу, итераторы `vector`, `sum`, `product`, `select`, `iterate`, `iterates`. Готовые программы — `examples\programs.mth`. Внутри вызовов аргументы-операторы разделяются запятыми, переносы строк внутри скобок — продолжение.

### Блоки и циклы

| Запись | Смысл |
|---|---|
| `prog(s1, s2, ..., sn)` | выполнить операторы по порядку, значение — последнего |
| `loop(s1, ..., sn)` | бесконечный цикл по телу; выход — `exit` |
| `exit`, `exit(v)` | выйти из ближайшего `loop`; значение цикла — `v` (без `v` — `false`) |
| `return(v)` | выйти из ближайшей функции языка (на верхнем уровне — завершить оператор) со значением `v` |
| `print(e1, e2, ...)` | напечатать значения в синтаксисе языка (для отладки); значение — последний аргумент. В REPL и файлах `.mth` печатает сразу; в `--json` — накапливается в поле `output` ответа |
| `set_loop_limit(n)` | предел числа итераций `loop` (и `iterate` до неподвижной точки), по умолчанию 1000000 |

Типичное использование — `if(условие, exit)`:

```
math> s := 0; k := 1
math> loop(if(k > 100, exit), s := s + k, k := k + 1)
false
math> s
5050
math> gcd2(a, b, t := 0) := prog(loop(if(b = 0, exit), t := mod(a, b), a := b, b := t), a)
math> gcd2(1071, 462)
21
```

Превышение лимита — понятная ошибка, а не зависание: `loop: превышен лимит итераций 1000000 (изменить: set_loop_limit(n); выход из цикла — exit)`. `exit` вне цикла и `exit` в функции без `loop` — ошибка «exit: вне цикла loop». Если условие `if` внутри цикла неопределённо (символьное), оно остаётся невычисленным и цикл не завершится — сработает лимит.

Внимание: `exit` — ещё и команда выхода из сеанса REPL, но только если это **вся введённая строка**; внутри программы (`loop(..., exit)`, в том числе на отдельной строке продолжения) это выход из цикла.

`return` — из середины цикла:

```
math> first_sq(lim) := prog(k := 1, loop(if(k*k > lim, return(k)), k := k + 1))
math> first_sq(50)
8
```

### Локальные переменные

Параметр со значением по умолчанию — локальная переменная. Недостающие аргументы при вызове заменяются значениями по умолчанию; они вычисляются **при вызове** и видят предыдущие параметры:

```
math> fact(n, r := 1, i := 2) := prog(loop(if(i > n, exit), r := r*i, i := i + 1), r)
math> fact(20)
2432902008176640000
math> c(a, b := a*2) := a + b
math> c(3)
9
```

Правила (как в Derive):

* присваивание внутри функции: если имя — параметр (в том числе по умолчанию), меняется локальная переменная; иначе — **глобальная переменная языка** (поэтому счётчики и накопители объявляйте параметрами);
* локальные переменные не портят глобальных одноимённых;
* параметры без значения по умолчанию должны идти раньше параметров со значением; вызов с лишним или недостающим числом аргументов — ошибка «ожидается аргументов от 1 до 2»;
* локальные значения — «обычные»: они не пересчитываются при использовании (лениво пересчитываются только глобальные переменные).

### Присваивание элементу

```
math> v := [1, 2, 3]
math> v[2] := 20
20
math> v
[1, 20, 3]
math> m := [[1, 2], [3, 4]]; m[2, 1] := 9
math> m
[[1, 2], [9, 4]]
```

Значения не разделяются: ранее взятые копии (`w := v` до присваивания, передача вектора в функцию) не меняются. Для скорости вектор, принадлежащий только этой переменной (созданный её предыдущим присваиванием элемента и ни разу не «выданный наружу» — не прочитанный целиком, только как `v[i]`), меняется **на месте**; иначе сначала копируется (один раз, дальше — на месте). Поэтому заполнение вектора в цикле — O(1) на присваивание, а чтение вектора целиком (`dimension(v)`, `w := v`, передача в функцию) между присваиваниями возвращает к копированию. Индексы и правая часть вычисляются **до** чтения вектора (если правая часть сама меняет `v`, изменения видны). Нужно по одному индексу на каждое измерение (присвоить целую строку нельзя); индекс вне границ — ошибка.

### Итераторы

Переменная итератора `k` — **локальная связанная переменная**: глобальное `k` не используется и не портится (даже если ему присвоено значение). Выражение вычисляется для каждого значения `k`.

| Запись | Результат |
|---|---|
| `vector(e, k, n)` | вектор значений выражения e при k = 1…n |
| `vector(e, k, m, n)`, `vector(e, k, m, n, step)` | `k` от `m` до `n` с шагом 1 или `step` (отрицательный — вниз) |
| `vector(e, k, v)` | `k` пробегает элементы вектора (или множества) `v`; вложенные результаты дают матрицу |
| `sum(e, k, m, n)`, `product(e, k, m, n)` (и формы как у `vector`) | явная сумма/произведение с упрощением |
| `sum(v)`, `product(v)` | сумма/произведение элементов вектора или множества |
| `select(c, k, v)` (и `select(c, k, m, n)`) | элементы, для которых условие `c` — `true` (неопределённое — не берётся) |
| `iterate(f(x), x, x0, n)` | n-кратная композиция: `f(f(...f(x0)))` |
| `iterates(f(x), x, x0, n)` | вектор `[x0, x1, ..., xn]` |
| `iterate(f(x), x, x0)` | итерировать до неподвижной точки (равенство после упрощения), предохранитель — лимит итераций |

```
math> vector(k^2, k, 5)
[1, 4, 9, 16, 25]
math> sum(x^k, k, 0, 3)
1 + x + x^2 + x^3
math> sum(x^k, k, 0, n)
sum(x^k, k, 0, n)
math> product(k, k, 1, 10)
3628800
math> iterates(x/2 + 1/x, x, 1, 3)
[1, 3/2, 17/12, 577/408]
math> iterate(cos(x), x, 1.0)
0.7390851332151607
math> select(mod(k, 2) = 0, k, 1, 10)
[2, 4, 6, 8, 10]
```



Символьные границы `sum` (без шага или с числовым шагом) вычисляются символьно (21l.1): каскад — константа, линейность, Фаульхабер (`sum(k^2, k, 1, n)` → многочлен Бернулли), `Σ 1/k^m` → `harmonic(n, m)`, геометрическая (`sum(q^k, k, 0, n)`, для символьного q — условие `q ≠ 1`); не распознанное тело — невычисленная форма `sum(...)` (статус unknown). Символьные границы `product` дают невычисленную форму `product(...)` (символьное произведение не реализовано). При присвоении границы значения форма вычисляется заново (`s := sum(x^k, k, 0, n); n := 2; s` → `1 + x + x^2`). Границы `vector`/`select` должны быть числами. Функция языка с тем же именем (`sum(a, b) := a*b`) перекрывает итератор.

Дальше в каскаде (шаги 21l.3–21l.5): **Госпер** — если тело гипергеометрично по k (`t(k+1)/t(k)` рационально), сумма телескопируется: `sum(C(n,k)^2*... , k, ...)` замкнутой формы может не иметь; найденное — точное рациональное `g(hi+1) − g(lo)`; **Абрамов** — рациональные тела (перенос полюсов, ψ-разности): `sum(1/(k*(k+2)), k, 1, n)` → рационально + ψ; **Цайльбергер** (`zb-par-gosper`) строит для ΣF(n,k) рекуррентность порядка J по n (форма `(recurrence S n (a0…aJ) rhs …)`), проверяемую численным оракулом `recurrence-check`; `wz-prove-identity` доказывает WZ-тождества (ΣC(n,k)=2ⁿ). Сертификаты — в справочнике библиотеки `docs/lisp-library-guide.md` § суммирование. Рекуррентность Цайльбергера затем решается (`rsolve`, 21l.6): порядок 1 → Γ-произведение с полировкой в биномы (`sum(C(n,k)^2, k, 0, n)` → `C(2n, n)`), постоянные коэффициенты → сумма экспонент; нет гипергеометрических решений (Апери) — ответом остаётся рекуррентность с начальными значениями.

Функции над векторами: `dimension(v)` (длина; для матрицы — `[строки, столбцы]`; для множества — число элементов), `append(v, w, ...)`, `reverse(v)`, `first(v)`, `rest(v)`, `last(v)`, `position(x, v)` (номер с 1 или 0). Накопление результата:

```
math> r := []; k := 1; loop(if(k > 5, exit), r := append(r, [k*k]), k := k + 1)
math> r
[1, 4, 9, 16, 25]
```

| Функция | Что делает |
|---|---|
| `dimension(v)` | длина вектора; для матрицы [строк, столбцов]; для множества — число элементов |
| `append(v, w, ...)` | сцепление векторов |
| `reverse(v)` | вектор в обратном порядке |
| `first(v)` | первый элемент |
| `rest(v)` | все элементы, кроме первого |
| `last(v)` | последний элемент |
| `position(x, v)` | номер первого вхождения элемента (с 1) или 0, если его нет |

## Встроенные функции

Любая функция библиотеки доступна по имени. Аргументы вычисляются заранее; результат упрощается. Имена с дефисом пишутся с подчёркиванием: `poly_gcd`, `set_difference`, `power_set`, `real_roots`.

От **точных** аргументов результат остаётся символьным (в отличие от Lisp-режима, где это числа с плавающей точкой); от дробных — считается численно; очевидные значения сворачиваются:

math> sin(0.5)

Точные значения (шаг 21c): `sin cos tan cot sec csc` от рациональных кратных π со знаменателем 1, 2, 3, 4, 6 (`sin(7π/6)` → `-1/2`, `tan(π/3)` → `3^(1/2)`), `exp(0)`, `log(1)`, `log(exp(1))`, `atan(1)` → `1/4*pi`, `acos(0)` → `1/2*pi` и другие табличные значения; полюса (`tan(π/2)`) не вычисляются. Степени `exp` сливаются: `exp(x)*exp(y)` → `exp(x + y)`, `1/exp(x)` → `exp(-x)`. Корни из рациональных чисел приводятся к виду «рациональный множитель · m^(1/q)» без знаменателя под корнем: `sqrt(72)` → `6*2^(1/2)`, `(1/2)^(1/2)` → `1/2*2^(1/2)`, `16^(1/4)` → `2`, `4^(1/4)` → `2^(1/2)` (числа свыше 10^12 не раскладываются и остаются как есть).

Факториал: `5!` → `120`; `n!` для символа остаётся `n!`.

### Комбинаторные функции

`binomial(n, k)` (также `C(n, k)`) — биномиальный коэффициент; `gamma(x)` — Γ(x), печатается `Γ(x)`; `psi(x[, m])` — дигамма/полигамма, печатается `ψ(x)`; `harmonic(n[, m])` — гармонические числа H_n, H_{n,m}; `bernoulli(n)` / `bernoulli(n, x)` — числа и многочлены Бернулли; `rf(a, k)` / `ff(a, k)` — растущий и убывающий символы Похгаммера (a)_k, (a)‾k.

От точных аргументов — точные значения (рациональная арифметика); от float — численно (`ψ` — только численно); символьные аргументы остаются невычисленными и упрощаются тождествами (`Γ(n+1)` → `n!`, `Γ(x+1)` → `x·Γ(x)`, `C(n, 0)` → `1` и др.). Производные: d/dx Γ(x) = Γ(x)·ψ(x), d/dx ψ(x) = ψ(x, 1), d/dx H(x) = ψ(x+1) + γ (γ — константа Эйлера `euler-gamma`).

```
math> C(10, 3) + gamma(5)
144
math> harmonic(4)
25/12
math> psi(2.0)
0.422784335089708
math> gamma(x+1)
x*Γ(x)
math> bernoulli(4)
-1/30
math> bernoulli(3, x)
1/2*x - 3/2*x^2 + x^3
```

Границы точных значений: Γ — целые аргументы до 5001; rf/ff — k ≤ 200; H — n ≤ 120; числа Бернулли — n ≤ 60, многочлены — n ≤ 30. ψ(1/2) = −γ − 2·ln 2 (символьное правило).

| Функция | Что делает |
|---|---|
| `binomial(n, k)` | биномиальный коэффициент C(n, k) |
| `gamma(x)` | гамма-функция Γ(x) |
| `psi(x[, m])` | дигамма-функция ψ(x) и полигамма ψ(x, m) |
| `harmonic(n[, m])` | гармонические числа H_n и H_{n,m} |
| `bernoulli(n[, x])` | числа Бернулли B_n или многочлены B_n(x) |
| `rf(a, k)` | растущий символ Похгаммера (a)_k = a(a+1)…(a+k−1) |
| `ff(a, k)` | убывающий символ Похгаммера (a)‾k = a(a−1)…(a−k+1) |

### Эллиптические интегралы

`EllipticF(φ, k)`, `EllipticE(φ, k)`, `EllipticE(k)`, `EllipticPi(n, φ, k)`, `EllipticK(k)`, `EllipticEC(k)` — неполные и полные эллиптические интегралы Лежандра (модуль k, параметр n). Имена вводятся и печатаются заглавными; в Lisp это головы `elliptic-f/e/pi/k/ec`. Символьные аргументы остаются невычисленными, численные считаются (Карлсон RF/RD, Π — квадратура).

```
math> EllipticF(x, 1/2)
EllipticF(x, 1/2)
math> EllipticK(1/2) + EllipticE(1/2)
EllipticE(1/2) + EllipticK(1/2)
math> integrate(1/sqrt(1-x^4), x)
-1/2*2^(1/2)*EllipticF(asin(2^(1/2)*x*(x^2 + 1)^(-1/2)), 1/2*2^(1/2))
```

Интегратор возвращает эти головы для табличных эллиптических интегралов (см. `lib/integrate/elliptic.lisp`): первый род — с условием `nonelementary`, второй (E) и третий (Π) — без отказа.

| Функция | Что делает |
|---|---|
| `EllipticF(φ, k)` | неполный эллиптический интеграл 1-го рода F(φ|k) |
| `EllipticE(φ, k)` | неполный эллиптический интеграл 2-го рода E(φ|k) |
| `EllipticE(k)` | полный эллиптический интеграл 2-го рода E(k) |
| `EllipticPi(n, φ, k)` | неполный эллиптический интеграл 3-го рода Π(n; φ|k) |
| `EllipticK(k)` | полный эллиптический интеграл 1-го рода K(k) |
| `EllipticEC(k)` | полный интеграл 2-го рода от параметра m = k² (форма, которой пользуется интегратор) |

### Бессель, Эйри, Лежандр

`BesselJ(ν, x)`, `BesselY(ν, x)`, `BesselI(ν, x)`, `BesselK(ν, x)` — функции Бесселя порядка ν (в Lisp головы `bessel-j/y/i/k`). `AiryAi(x)`, `AiryBi(x)` и их производные `AiryAiPrime(x)`, `AiryBiPrime(x)` — функции Эйри (`airy-ai/bi/ai-prime/bi-prime`); `Ai″ = x·Ai`, так что `diff` замыкается. `LegendreP(n, x)`, `LegendreQ(n, x)` — многочлены Лежандра 1-го и 2-го рода (`legendre-p/q`). Печать и чтение — круговые: `BesselJ(0, x)` читается обратно в ту же голову.

Полуцелый порядок Бесселя (|ν| ≤ 9/2) сразу даёт элементарную форму: `BesselJ(1/2, x)` → `sqrt(2/(πx))·sin x`, `BesselJ(-1/2, x)` → `sqrt(2/(πx))·cos x` (аналогично Y, I, K). Целый n ≥ 0 у `LegendreP` — многочлен. Численные значения — через `eval-num` (вещественный аргумент): Ai(0) = 0.3550280538878172, J₀(1) = 0.7651976865579666; при аргументе вне вещественной области (`BesselY(0, -1)`, `LegendreQ(0, 1)`) значения нет.

```
math> BesselJ(1/2, x)
2^(1/2)*sin(x)/(pi^(1/2)*x^(1/2))
math> LegendreP(3, 1/2)
-7/16
math> diff(AiryAi(x), x)
AiryAiPrime(x)
```

| Функция | Что делает |
|---|---|

### Целые числа и экстремумы

`gcd(a, b, ...)`, `lcm(a, b, ...)` — НОД и НОК целых (n-арные; `gcd()` = 0, `lcm()` = 1); `quotient(a, b)` — частное с усечением к нулю; `remainder(a, b)` (и `mod`) — остаток со знаком делимого; `modulo(a, b)` — остаток со знаком делителя; `min(a, b, ...)`, `max(a, b, ...)` — числа любой точности (при наличии float результат float); от символа и комплексного числа — ошибка (невычисленных форм `min`/`max` нет). Деление на ноль — ошибка.

```
math> gcd(12, 18) + lcm(4, 6) + max(1/2, 1/3)

math> modulo(-7, 2)

```

### ОДУ

Неизвестная функция — `y(x)`; штрихи `y′`, `y″`, `y‴` читаются как производные по `x`, а `y′(0)` — как значение
производной в точке (голова `at`).

| Функция | Что делает |
|---|---|
| `dsolve(уравнение, y(x))` | решение ОДУ: квадратуры `y⁽ⁿ⁾ = f(x)`, первый порядок, линейные с постоянными коэффициентами, уравнение Эйлера–Коши (`n ≤ 4`), ответ `(ode-solution …)`; вне известных методов `:status unknown` |
| `dsolve(уравнение, y(x), y(x0) = v, y'(x0) = w, …)` | задача Коши: условия `y(x0) = v`, `y'(x0) = w` и старших порядков; частное решение `:type particular` с сертификатом; несовместные условия — `:status unknown` с причиной |
| `dsolve(y'' + y = 0, y(t), y(0) = 1, y'(0) = 0)` | независимая переменная штрихов `y'`, `y''`, `y'(0)` берётся из `y(t)` второго аргумента `dsolve` (по умолчанию `x`); явная `diff(y(x), x)` при `y(t)` — не тот же аргумент, ответ `unknown` |
| `ode_check(уравнение, решение, y(x))` | сертификат подстановкой (`true`/`false`; численный запасной путь) |

```

math> dsolve(y'' + y = 0, y(x), y(0) = 1, y'(0) = 0)

math> ode_check(y' = x^2, y = 1/3*x^3 + C1, y(x))

```

| Функция | Что делает |

| `integrate(e, x)` | неопределённый интеграл |

```
math> diff(x^3, x, 2)

math> integrate(x^2, x, 0, 1)

math> limit(sin(x)/x, x, 0)

math> limit((1 + 1/x)^x, x, ∞)

math> limit(1/x, x, 0, plus)

math> series(sin(x), x, 0, 6)

math> taylor(exp(x), x, 0, 4)

```

Если интеграл или предел найти не удалось, возвращается невычисленная форма: `integrate(foo(x), x)`.

**Алгоритм Риша: что умеет `integrate` для `exp`, `log`, `atan` (шаги 21k.1–21k.6).** Последняя стратегия каскада (после неё — невычисленная форма): подынтегральная функция переписывается в башне `ℚ(x)(θ₁)…(θₙ)` (θ — `log`, `exp`, `atan` от элементов башни; независимость — структурная теорема), затем редукция Эрмита, логарифмическая часть (Лазар–Риобу–Трагер), многочленная часть и уравнение Риша `Dy + f·y = g` для экспонент. Три исхода:

* **ответ** — элементарная первообразная, проверенная дифференцированием: `integrate(1/(1 + exp(x)), x)` → `x - log(1 + exp(x))`; `integrate(x^x*(1 + log(x)), x)` → `x^x`; `integrate((x + 1)*exp(x)/(x*exp(x) + 1), x)` → `log(1 + x*exp(x))`; `integrate(atan(x), x)`;
* **частичный ответ** — элементарная часть плюс остаток, **доказанно неэлементарный**: `integrate(log(log(x)), x)` → `x*log(log(x)) - integrate(1/log(x), x)` (`status: answer`, остаток — в `conditions` как `risch-nonelementary`); определённый интеграл от такого ответа не вычисляется. С шага 21k.7b — и для экспонент (частичные решения уравнения Риша): `integrate(exp(x)/x^2, x)` → `-exp(x)/x + integrate(exp(x)/x, x)`, `integrate(exp(x)*log(x), x)` → `exp(x)*log(x) - integrate(exp(x)/x, x)`, `integrate(x^2*exp(x^2), x)` → `1/2*x*exp(x^2) - 1/2*integrate(exp(x^2), x)`;
* **неэлементарно** — `integrate(exp(x^2), x)`, `exp(-x^2)`, `exp(x)/x`, `1/log(x)`, `x^x`, `exp(exp(x))`, `x/(1 + exp(x))`, `log(x)/log(1 + x)` остаются невычисленной формой, а `status` в JSON/MCP — `nonelementary` (причина — в `note`). Это ответ, а не отказ. «Не знаю» (обратная тригонометрия, `sqrt`, `erf`, алгебраика, ветви без PRDE) — обычный `unknown`: Риш никогда не выдаёт «неэлементарно» без доказательства.

**Тригонометрия в Рише (шаг 21k″).** `sin`, `cos`, `tan`, `cot`, `sec`, `csc` с кратными углами переписываются через θ = tan(x/2) (половинный угол) или tan x (только tan/cot); специальный множитель знаменателя — `1 + θ²`. Доказано неэлементарными (`status: nonelementary`): `sin(x)/x`, `cos(x)/x`, `sin(x²)`, `cos(x²)`, `sin(x)/(x+1)`, `exp(x)·tan(x)`, `x·tan(x)`, `exp(x)/(1 + tan x)`. Берутся то, что прежние приёмы не брали: `integrate(1/(2 + cos(x)), x)`, `1/(2 + sin(x))`, производные `sin(x)/x`, `x/sin(x)`. Ответ через `tan(x/2)` разрывен в нулях `cos(x/2)` (условие `risch-tan-branch`), поэтому определённый интеграл подстановкой пределов через такой ответ не вычисляется — остаётся невычисленная форма. Нет: tan рядом с `atan`, под `exp`/`log`, вложенная тригонометрия, несвязанные углы (`sin x` и `sin x²`), система над башней с `exp` (например `exp(x)·sin(x)²` Риш не решает) — `unknown`.

Параметры в показателе (`exp(a*x)`) считаются генерическими (условие `risch-generic`). **Специальные функции — только дополнительно:** `integrate` по умолчанию не меняется, а `risch_special(f, x)` (таблица: `exp(-a x²)` → `erf`, `exp(k x²)` → `erfi`, `exp(a x)/x` → `Ei`, `1/log x` → `li`, `sin(a x)/x` → `Si`, `cos(a x)/x` → `Ci`) возвращает первообразную с ними:

```
math> integrate(exp(-x^2), x)
integrate(exp(-x^2), x)
math> risch_special(exp(-x^2), x)
1/2*pi^(1/2)*erf(x)
math> risch_special(log(log(x)), x)
x*log(log(x)) - li(x)
```

Причина условия `risch-nonelementary` (поле `note`) называет специальную функцию. `risch_integrate(f, x)` — запуск алгоритма Риша без остальных стратегий (`#f` — «не знаю» или неэлементарно целиком).

**Специальные функции (шаги 21k.6′, SF): `erf`, `erfc`, `erfi`, `Ei`, `li`, `Si`, `Ci`, `Shi`, `Chi`.** Производные заведены в `diff` (цепное правило): `d/dx erf(u) = 2/√π·e^(−u²)·u′`, `erfc` — с минусом, `erfi` — `e^(u²)`, `Ei(u)′ = e^u·u′/u`, `li(u)′ = u′/ln u`, `Si(u)′ = sin(u)·u′/u`, `Ci(u)′ = cos(u)·u′/u`, `Shi`/`Chi` — через `sinh`/`cosh`; результат `risch_special` проверяется обычным `diff`/`int_check`. Упрощения (правила `simplify`, применяются автоматически): значения в нуле `erf(0) = erfi(0) = Si(0) = Shi(0) = 0`, `erfc(0) = 1`; нечётность `erf(−u) = −erf(u)` и так же `erfi`, `Si`, `Shi` (при доказуемо отрицательном числовом множителе аргумента; знак символьного множителя неизвестен — остаётся как есть). `erfc(u)` сознательно НЕ переписывается в `1 − erf(u)`; `Ei`, `li`, `Ci`, `Chi` значений и чётности не имеют — не упрощаются.

**Пределы: что умеет `limit` (шаг 21j.3).** Сначала работает прежний каскад (подстановка и пределы частей, ряды Лорана, `f^g = exp(g·log f)`, Лопиталь, вынесение слагаемого, модуль), и только если он не взял предел, подключается **алгоритм Грунца** (сравнение скоростей роста, MRV) для выражений с `exp`, `log`, гиперболическими функциями и степенями с `x` в показателе. Предел сводится к `x → +∞` (`x → −∞`: `x = −t`; `x → a±`: `x = a ± 1/t`; двусторонний предел — обе стороны, разные — `undefined`). Теперь берутся, например:

```
math> limit(x - log(1 + exp(x)), x, ∞)
0
math> limit((3^x + 5^x)^(1/x), x, ∞)
5
math> limit(x*exp(x)/(exp(x) + 1), x, -∞)
0
math> limit(exp(-1/x)/x, x, 0, plus)
0
math> limit(exp(1/x), x, 0)
undefined
```

Знак параметра берётся только из деклараций: `limit((a^x + 5^x)^(1/x), x, ∞)` без `a :∈ positive` и без известного соотношения `a` и 5 остаётся невычисленным (причина — в `conditions`). Поведение выбирается переключателем `(set-algorithm 'limit …)` (Lisp) / `set_algorithm(limit, …)` (язык): `auto` (по умолчанию — старый каскад, затем Грунц), `classic` (без Грунца — как до шага 21j.3), `gruntz` (только Грунц: быстрее на сложных башнях exp-log, но `sin x`, `|x|` и т. п. не берёт). Шаги: `steps(limit(...), "full")` показывает «Сравнение скоростей роста (алгоритм Грунца)» с подшагами замены, MRV-множества и ведущего члена.

**Рациональные функции (шаг 21h).** Интеграл любой рациональной функции от `x` над ℚ (с параметрами в коэффициентах — тоже) вычисляется всегда: деление с остатком, редукция Эрмита (рациональная часть без факторизации знаменателя), логарифмическая часть — Лазар–Риобу–Трагер (субрезультантная ПРС). Простые случаи (линейные и квадратные множители) дают прежние ответы; остальное — новый запасной путь:

* вычеты в ℚ: `a*log(...)`; пара сопряжённых корней: если все параметры вещественны (`a :∈ reals`; необъявленный символ — элемент ℂ) — вещественная форма Риобу: атаны **многочленов** и логарифмы (на вещественной оси без разрывов, поэтому `F(b) − F(a)` верно); иначе — корни в радикалах с `i`;
* корни Q не выражаются явно — сумма по корням `rootsum` (комплексная форма).

```
math> integrate((x^4 - 3x^2 + 6)/(x^6 - 5x^4 + 5x^2 + 4), x)
atan(x) + atan(x^3) + atan(1/2*x - 3/2*x^3 + 1/2*x^5)
math> integrate(1/(x^4 + 1), x)
rootsum(t*log(4t + x), t, 1 + 256t^4)
math> integrate((x^4 - 3x^2 + 6)/(x^6 - 5x^4 + 5x^2 + 4), x, -∞, ∞)
3pi
```

Определённый интеграл от ответа с `rootsum` вычисляется, только если ветвь логарифма не пересекает разрез на `[a, b]` (проверяется: у аргумента `log` коэффициенты при `x^k`, k ≥ 1, не зависят от `t`, либо числовая проверка непрерывности); иначе — невычисленная форма.

**`rootsum(E, t, Q)`** — сумма выражения `E` по корням `t` многочлена `Q` (с учётом кратности). Lisp-форма — `(root-sum t Q E)` (переменная и многочлен — первыми, как у `root-of`; порядок аргументов языка — по образцу `sum(e, k, ...)`: выражение первым). Каноническая форма: связанная переменная переименована (`t`, `s`, `u`, … — первое имя, не входящее свободно), `Q` — примитивный неприводимый над ℚ(параметры); сумма раскладывается по слагаемым и по множителям `Q`, множитель без `t` выносится, линейный множитель — подстановка корня, многочлен `E` — степенные суммы (формулы Ньютона). `diff` — внутрь (при зависимости `Q` от переменной — с поправкой на движение корней), `subst` — без захвата связанной переменной, `eval-num` — численно (рациональное тело считается точно по модулю `Q`).

```
math> rootsum(t^2, t, t^3 - t - 1)
2
math> diff(rootsum(t*log(x + t), t, t^3 + t + 1), x)
rootsum(t/(t + x), t, 1 + t + t^3)
```

| Функция | Что делает |
|---|---|
| `risch_integrate(f, x)` | только алгоритм Риша, без остальных стратегий (#f — «не знаю») |
| `risch_special(f, x)` | интеграл через специальные функции; вызывается явно, обычный integrate не меняется |
| `Ei(u)` | интегральная показательная функция Ei(u) |
| `li(u)` | интегральный логарифм li(u) |
| `Si(u)` | интегральный синус Si(u) |
| `Ci(u)` | интегральный косинус Ci(u) |
| `erf(u)` | функция ошибок erf(u) |
| `erfc(u)` | дополнительная функция ошибок erfc(u) |
| `set_algorithm(limit, mode)` | переключатель алгоритма предела: auto (каскад, затем Грунц), classic, gruntz |
| `rootsum(E, t, Q)` | сумма выражения E по корням t многочлена Q (с кратностями) |

### Уравнения

`solve(уравнение, x)` возвращает **множество** решений; уравнение — `левая = правая` (или выражение, подразумевается `= 0`). Системы — векторами: `solve([ур1, ур2], [x, y])`; каждое решение — вектор уравнений.

```
math> solve(x^2 - 5x + 6 = 0, x)
{2, 3}
math> solve(x^2 = 2, x)
{2^(1/2), -2^(1/2)}
math> solve([x + y = 3, x - y = 1], [x, y])
{[x = 2, y = 1]}
```

Результат зависит от деклараций неизвестной (см. выше): без деклараций ищутся комплексные корни.

Нелинейные системы многочленов с рациональными коэффициентами решаются через базис Грёбнера (lex, переменные — в порядке
запроса): система приводится к треугольному виду, последний многочлен — от одной переменной. Несовместная система даёт `{}`;
бесконечно много решений — ошибка. Корни, не выражающиеся в радикалах, дают решение через `root_of`: остальные неизвестные —
многочлены от корня (как и для одного уравнения: вещественные корни f — явно, `root_of(f, x)` — остальные, невещественные). Символы вне списка неизвестных — **параметры**: ответ верен для
общих значений параметров (условия видны в журнале шагов); система, совместная лишь при особых значениях параметров, — ошибка
с условием; `root_of` при параметрах не поддерживается.

```
math> solve([x^2 + y^2 = 5, x*y = 2], [x, y])
{[x = -2, y = -1], [x = -1, y = -2], [x = 1, y = 2], [x = 2, y = 1]}
math> solve([x^2 + y^2 + z^2 = 6, x + y + z = 4, x*y*z = 2], [x, y, z])
{[x = 1, y = 1, z = 2], [x = 1, y = 2, z = 1], [x = 2, y = 1, z = 1]}
```

| Функция | Что делает |
|---|---|
| `solve(уравнение, x)` | множество решений уравнения (или системы) |
| `root_of(f, x)` | формальный корень многочлена f по x, когда явной формулы нет |

### Базисы Грёбнера

`groebner([многочлены], [переменные])` — приведённый базис Грёбнера идеала (вектор монических многочленов; первая
переменная — старшая); третий аргумент — порядок мономов `lex` (по умолчанию), `grlex`, `grevlex`. Многочлен можно
записать уравнением (`x^2 = 2` означает `x^2 - 2`); коэффициенты — рациональные числа. Базис `[1]` — система несовместна.
`normal_form(f, [образующие], [переменные])` — остаток f по модулю соотношений (упрощение с учётом связей; символы вне
списка переменных — параметры). `eliminate([многочлены], [исключаемые], [остальные])` — исключение переменных.

```
math> groebner([x^3 - 2x*y, x^2*y + x - 2y^2], [x, y], grlex)
[x^2, x*y, -1/2*x + y^2]
math> normal_form(x^3 + y^3, [x^2 - y, y^2 - x], [x, y], grevlex)
2x*y
math> normal_form(x^2 + a, [x^2 = 2], [x])
2 + a
math> eliminate([x - t^2, y - t^3], [t], [x, y])
[x^3 - y^2]
```

| Функция | Что делает |
|---|---|
| `groebner([многочлены], [переменные])` | приведённый базис Грёбнера идеала |
| `normal_form(f, [образующие], [переменные])` | остаток f по модулю соотношений (упрощение с их учётом) |
| `eliminate([многочлены], [исключаемые], [остальные])` | исключение переменных из системы |

### Ряды Пюизё

`puiseux(F, x, y, n)` — ветви разложения F(x, y) = 0 в окрестности x = 0 (ряды Ньютона–Пюизё):
вектор ветвей `(q термы)`, y = Σ cᵢ·x^{eᵢ} (eᵢ — рациональные со знаменателем q), ряд — до порядка
x^n включительно; каждая ветвь проверяется подстановкой. См. `docs/lisp-library-guide.md` § puiseux.

```
math> puiseux(y^2 - x^3, x, y, 3)
[(2 ((1 3/2))), (2 ((-1 3/2)))]
```

| Функция | Что делает |
|---|---|
| `puiseux(F, x, y, n)` | ветви разложения F(x, y) = 0 в окрестности x = 0 до порядка n |

### Дифференциальные формы и векторный анализ

Форма — обычное выражение с символами `dx`, `dy`, … (имя переменной с приставкой `d`); **список переменных — последним аргументом**.
Формы степени ≥ 2 пишите через `wedge(dy, dz)` (без вектора переменных это формальная запись): `*` в языке коммутативно,
`dz*dx` превратилось бы в `dx*dz` и знак потерялся бы.

| Вызов | Результат |
|---|---|
| `wedge(a, b, …, [x, y, …])` | внешнее произведение (с вектором переменных — вычисляется, без него — формальная запись) |
| `extd(w, [x, y])` | внешний дифференциал dω |
| `pullback(w, [x, y], [φ₁, φ₂], [u, v])` | прообраз при x = φ₁(u, v), y = φ₂(u, v) |
| `hodge(w, [x, y, z])`, `interior(v, w, [x, y, z])` | ∗ω в евклидовом ℝⁿ; внутреннее произведение ι_v ω (v — вектор) |
| `grad(f, vars)`, `div(F, vars)`, `curl(F, vars)`, `laplacian(f, vars)` | векторный анализ через формы (curl — вектор в ℝ³, скаляр Q_x − P_y в ℝ²) |
| `potential(F, vars)`, `vector_potential(F, [x, y, z])` | потенциал консервативного поля / векторный потенциал при div F = 0; `false`, если нет (с проверкой) |
| `form_potential(w, vars)` | потенциал замкнутой формы по Пуанкаре (звёздная область вокруг 0); не замкнута или особенность в 0 → `false` |
| `integrate_form(w, vars, [φ…], [t, a, b] …)` | ∫ формы по кривой (один диапазон) или поверхности (два): прообраз + определённый интеграл |

```
math> form_potential(2*x*y*dx + (x^2 + 3*y^2)*dy, [x, y])
y^3 + x^2*y
math> pullback(wedge(dx, dy), [x, y], [r*cos(th), r*sin(th)], [r, th])
r*wedge(dr, dth)
math> integrate_form(-y*dx + x*dy, [x, y], [cos(t), sin(t)], [t, 0, 2*pi])
2pi
```

Пример: `examples/19-differential-forms.mth`; Lisp-функции — `docs/lisp-library-guide.md` § forms. Если символьный интеграл не берётся,
`integrate_form` даёт численное значение (Симпсон) и условие `(integrate-form-numeric)`.

### Особые точки и род кривой

`genus(F, x, y)` — род неприводимой алгебраической кривой F(x, y) = 0 по формуле Нётера
g = (d−1)(d−2)/2 − Σ δ_P (сумма δ-инвариантов всех особых точек проективной замыкания,
включая бесконечно удалённые и точки над расширениями ℚ̄). Ответ `(genus g)`;
приводимая кривая → `(reducible множители)`; нераскрытая группа → `unknown`.

`singular_points(F, x, y)` — группы сопряжённых особых точек (аффинные и бесконечно удалённые):
`((point a b) (multiplicity m) (branches r) (delta δ) (ordinary #t/#f) (tangents …) (conjugates e)
(at affine|inf))`. См. `docs/lisp-library-guide.md` § curves.

```
math> genus(y^2 - x^3, x, y)
genus(0)
math> genus(y^2 - x^3 - x - 1, x, y)
genus(1)
math> singular_points(y^2 - x^2*(x+1), x, y)
(((point 0 0) (multiplicity 2) (branches 2) (delta 1) (ordinary #t) (tangents ((slope -1) (slope 1))) (conjugates 1) (at affine)))
```

| Функция | Что делает |
|---|---|
| `genus(F, x, y)` | род неприводимой кривой F(x, y) = 0 по формуле Нётера |
| `singular_points(F, x, y)` | группы сопряжённых особых точек — аффинных и бесконечно удалённых |

### Отладка упрощения

`trace_simplify(e)` печатает (как `print`: в `--json` — в поле `output`) шаги упрощения выражения и возвращает результат; `simplify_steps(e)` возвращает вектор шагов `[имя, до, после]`. Аргумент **не вычисляется** заранее (иначе упрощение произошло бы до трассировки): берётся как записано, значения присвоенных переменных не подставляются.

```
math> trace_simplify(sin(π/2) + 2*x + 3*x)
[exact-value] sin(1/2*pi) → 1
[collect-terms] 1 + 2x + 3x → 1 + 5x
1 + 5x
```

Имена преобразований: `collect-terms`, `merge-powers`, `exact-value`, `exact-root`, `extract-root`, `exp-merge`, `exp-power`, `power-of-product`, `power-of-power`, `imaginary-power`, `distribute-minus`, `pythagorean`, `trig-rules`, `sqrt-rational`, `sqrt-negative`, `ln-to-log`, `rule:имя` (правило `defrule`), `method:операция` (метод пользовательского типа). Журнал ограничен 500 шагами (затем строка `…усечено`). В Lisp: `(trace-simplify e)`, `(simplify-steps e)` → `((имя до после) ...)`.

| Функция | Что делает |
|---|---|
| `trace_simplify(e)` | печатает шаги упрощения выражения (в --json — поле output) |
| `simplify_steps(e)` | список шагов упрощения выражения |

### Пошаговые решения

`steps(выражение)` вычисляет выражение с журналом шагов, печатает решение деревом (как `print`: в `--json`/MCP — в поле `output`) и возвращает значение; `steps(выражение, "full")` — всё дерево (по умолчанию `"brief"` — только главные шаги верхнего уровня; `"trace"` — плюс каждое преобразование упрощателя). Третий аргумент — язык заголовков и пояснений (шаг S.5): `steps(выражение, "full", "en")`, `step_list(выражение, "full", "en")`; `"ru"` — по умолчанию. Английский перевод — словарь `src\Cas.Algebra\StepDict.fs` (`rule` не переводится, формулы и выражения остаются; совокупность решений по-русски печатается `x = 2 или x = 3`, по-английски — `x = 2 or x = 3`); шаг без перевода остаётся русским, последняя строка печати сообщает его `rule`. В Lisp: `(steps e 'full 'en)`, `(steps-translate 'en шаги)`. `step_list(выражение [, уровень [, язык]])` — шаги как данные: вектор записей `[путь, rule, заголовок, пояснение, до, после, уровень, скрыто]` в порядке обхода (путь `"1"`, `"1.1"`, … задаёт вложенность; по умолчанию `"full"`). В отличие от `trace_simplify`, выражение вычисляется (внутри журнала). Шаги пишут операции по мере готовности (шаг S): пока — `diff`, `simplify`, `integrate`, `solve`, `limit`, `series` и базисы Грёбнера; у остальных — «(шаги не записаны)». В `steps(integrate(...))`, `steps(diff(...))`, `steps(simplify(...))`, `steps(solve(...))`, `steps(limit(...))` и `steps(series(...))` первый аргумент (у `solve` — уравнение) берётся **как записан** (арифметика языка его не упрощает: шаги начинаются с того, что написал пользователь; значения присвоенных имён подставляются; выражение с функциями пользователя вычисляется как обычно).

Дифференцирование: верхний шаг `differentiation`, внутри — по шагу на правило (`diff-sum`, `diff-constant-multiple`, `diff-product`, `diff-quotient`, `diff-power`, `diff-power-general`, `diff-chain` — внешняя и внутренняя функции, `diff-exp`, `diff-log`, `diff-sqrt`, `diff-abs`, `diff-trig`, `diff-hyperbolic`, `diff-inverse-trig`, `diff-inverse-hyperbolic`; листья `diff-variable`, `diff-constant` — detail) и шаг `simplify-result` (detail). Производная подвыражения в «до» печатается как `d/dx(u)` (в цепном правиле внешняя функция — по формальной переменной: `d/du(sin(u))`). В `steps(diff(...))` аргумент берётся как записан, поэтому `(x+1)/(x-1)` даёт правило частного (вне `steps` и в MCP-инструменте `diff` с `syntax: math` аргумент уже упрощён арифметикой языка).

```
math> steps(diff(x^2*sin(x), x), "full")
1. Дифференцирование по x: d/dx(x^2*sin(x)) ⇒ 2x*sin(x) + x^2*cos(x)
   1.1 Правило произведения: d/dx(x^2*sin(x)) ⇒ 2x*sin(x) + x^2*cos(x)
       (u·v)' = u'·v + u·v'
       1.1.1 Производная степенной функции: d/dx(x^2) ⇒ 2x

       1.1.2 Производная тригонометрической функции: d/dx(sin(x)) ⇒ cos(x)
             (sin(x))' = cos(x)
   1.2 Упрощение результата: 2x^(2 - 1)*1*sin(x) + x^2*cos(x)*1 ⇒ 2x*sin(x) + x^2*cos(x)
2x*sin(x) + x^2*cos(x)
```

Упрощение: `steps(simplify(e), "full")` — шаг `simplification`, внутри сработавшие преобразования упрощателя (`simplify:pythagorean`, `simplify:collect-terms`, … — те же имена, что у `trace_simplify`, заголовки по-русски; в `brief` — только «исходное ⇒ упрощённое»). Как и `trace_simplify`, аргумент берётся как записано (не вычисляется заранее); выражение, которое упрощать нечего, шага не даёт. В Lisp: `(step-simplify e)`.

Интегрирование: верхний шаг `integration` («Интегрирование по x»: `∫ f dx ⇒ F`), внутри — применённая стратегия каскада; неудачные попытки в журнал не попадают. «До» — невычисленный интеграл, печатается `∫ f dx` (определённый — `∫_a^b f dx`); формулы приёмов — в пояснении. rule: `int-table` (табличный интеграл, в пояснении — формула), `int-linearity` (сумма — почленно; постоянный множитель), `int-substitution` (+ `int-substitution-change` «u = g, du = g′ dx», интеграл по `u`, `int-back-substitution`), `int-by-parts` (+ `int-parts-choice` «Выбор u и dv» с вложенным шагом ∫ dv = v, затем `int-parts-formula`; `int-parts-cycle` — циклический случай), `int-trig-powers` (приём для степеней sin/cos), `int-trig-product` (+ `int-product-to-sum`), `int-partial-fractions` (+ `apart`, `int-partial-fraction-term`), `int-rational-function` (Эрмит и ЛРТ: `int-rational-hermite` — рациональная часть, `int-rational-lrt` — логарифмическая часть, `rootsum`), `int-sqrt-quad`, `int-expand`, определённый — `int-definite` (+ `int-limits`: F(b) − F(a), или `int-improper`: пределы первообразной), детали `simplify-integrand`, `simplify-result`. Определённый интеграл (DI.3): бесконечные пределы, особенность внутри промежутка или отказ первообразной идут через модуль `definite` (вычеты, таблицы, замочная скважина); расходимость — невычисленная форма и условие `(divergent …)`; сертификат MCP — kind `definite`.

```
math> steps(integrate(x*exp(x), x), "full")
1. Интегрирование по x: ∫ x*exp(x) dx ⇒ x*exp(x) - exp(x)
   1.1 Интегрирование по частям: ∫ x*exp(x) dx ⇒ x*exp(x) - exp(x)
       ∫ u dv = u·v − ∫ v du; u выбирается по правилу LIATE (логарифм, обратная тригонометрия, алгебраическая, тригонометрия, показательная)
       1.1.1 Выбор u и dv: ∫ x*exp(x) dx ⇒ [u = x, dv = exp(x)*dx]
             по правилу LIATE; du = 1 dx; v = ∫ dv = exp(x) (вложенный шаг ниже)
             1.1.1.1 Табличный интеграл: ∫ exp(x) dx ⇒ exp(x)
                     ∫ exp(u) du = exp(u)
       1.1.2 Формула интегрирования по частям: ∫ x*exp(x) dx ⇒ x*exp(x) - ∫ exp(x) dx
             ∫ u dv = u·v − ∫ v du; здесь u = x, v = exp(x), du = 1 dx
       1.1.3 Табличный интеграл: ∫ exp(x) dx ⇒ exp(x)
             ∫ exp(u) du = exp(u)
x*exp(x) - exp(x)
math> steps(integrate(2*x*cos(x^2), x), "full")
1. Интегрирование по x: ∫ 2x*cos(x^2) dx ⇒ sin(x^2)
   1.1 Вынесение постоянного множителя: ∫ 2x*cos(x^2) dx ⇒ sin(x^2)
       ∫ c·f dx = c·∫ f dx, где c = 2
       1.1.1 Метод подстановки: ∫ x*cos(x^2) dx ⇒ 1/2*sin(x^2)
             u = x^2, du = 2x dx
             1.1.1.1 Замена переменной: ∫ x*cos(x^2) dx ⇒ ∫ 1/2*cos(u) du
                     подынтегральное выражение через u: 1/2*cos(u) du
             1.1.1.2 Вынесение постоянного множителя: ∫ 1/2*cos(u) du ⇒ 1/2*sin(u)
                     ∫ c·f dx = c·∫ f dx, где c = 1/2
                     1.1.1.2.1 Табличный интеграл: ∫ cos(u) du ⇒ sin(u)
                               ∫ cos(u) du = sin(u)
             1.1.1.3 Обратная замена: 1/2*sin(u) ⇒ 1/2*sin(x^2)
                     u = x^2
sin(x^2)
```

Решение уравнений: верхний шаг `solve-equation` («Решение уравнения относительно x»: уравнение как записано ⇒ множество решений), внутри — по порядку: `solve-move-terms` (a = b ⇒ a − b = 0), `solve-clear-denominator` (дробь: числитель = 0) и `solve-exclude-denominator-roots`, затем решение числителя — многочлен: `solve-linear` (ax + b = 0 ⇒ x = −b/a), `solve-quadratic` (a, b, c, дискриминант D = b² − 4ac и число корней; **только для неприводимого** квадратного трёхчлена — иррациональные/комплексные корни), `solve-factor` («после» — произведение множителей, дети — решения каждого множителя; так показывается и квадратное уравнение с рациональными корнями — алгоритм раскладывает его на множители), `solve-polynomial` (неприводимый многочлен степени ≥ 3: корни — алгебраические числа по Штурму, невещественные — `root-of`; формул Кардано/Феррари в `solve` нет); не многочлен — `solve-substitution` (замена t = sin(x), exp(x), …: «после» — многочлен от t; дети — решение по t и обращение), `solve-inverse-function` (sin, cos, tan, exp, log, abs, степень: обращение, серии `k1`, `k2` — целые), `solve-isolate` (перенос слагаемого, деление на множитель без x), `solve-square` (радикал: A + B√w = 0 ⇒ A² − B²w = 0), `solve-trig-ratio` (a·sin w + b·cos w = 0 ⇒ tan w = −b/a); отбор корней — `solve-check-roots` (проверка подстановкой убрала посторонние) и `solve-domain-filter` (отброшены по объявленной области значений) — только если что-то отброшено. Линейная система — одна крупная рамка `solve-linear-system` (метод Гаусса–Жордана: единственное решение / недоопределена / несовместна); нелинейная — `polynomial-system` (см. ниже). Уравнение в `steps(solve(...))` берётся как записано.

Пределы: верхний шаг `limit` («Предел при x → a», `limit(f, x, a) ⇒ значение`), внутри — сработавший приём каскада (неудачные не пишутся): `limit-substitution` (функция непрерывна, предел = значение), `limit-combine` (сумма/произведение/степень пределов частей; в пояснении `lim … = …`), `limit-series` (ведущий член ряда: k > 0 — предел 0, k = 0 — коэффициент, k < 0 — бесконечность), `limit-infinity` (x → ±∞: замена x = ±1/t, внутри — `limit-series` по t), `limit-power` (f^g = exp(g·log f); дочерний `limit-power-exponent` — предел показателя), `limit-lhopital` («неопределённость 0/0 или ∞/∞», дочерний `limit-derivatives`: числитель и знаменатель дифференцируются, затем предел отношения производных), `limit-factor-leading` (T1 + T2 = T1·(1 + T2/T1)), `limit-abs` (раскрытие модуля по знаку). «До» и «после» — невычисленные формы `limit(f, x, a)` (проверку эквивалентности `checkSteps` они не проходят — пропускаются). Ряды: верхний шаг `series` («Разложение в ряд Тейлора (Лорана) в точке a до порядка n»), внутри — `series-known` (стандартное разложение: exp, sin, cos, log(1+u), бином, …; в пояснении формула), `series-compose` (подстановка ряда аргумента в стандартное разложение), `series-arith` (сумма, произведение, частное, степень рядов), `series-derivatives` (запасной путь через производные); «после» — ряд с остатком `O(x^n)`. Внутренние операции над коэффициентами не пишутся. В `steps(limit(...))`, `steps(series(...))` первый аргумент берётся как записан.

Шаг: `rule` — стабильный английский идентификатор приёма (`polynomial-system`, `groebner-basis`, `fglm`), заголовок и пояснение — по-русски; каждый шаг — эквивалентное преобразование (или переход «система → базис», «уравнение → решения»). Дерево ограничено глубиной 8 и 200 шагами; скрытое помечается строками «… скрыто вложенных шагов: N» и «… шаги обрезаны: показано N из M». `steps` и `step_list` — особые формы языка (как `trace_simplify`): функцию с этими именами определить нельзя. В Lisp: `(steps выражение ['full])`, `(capture-step-log thunk ['full])` (`docs\lisp-library-guide.md` §4).

|---|---|
| `step_list(выражение, "full", "en")` | шаги решения списком; второй аргумент — уровень, третий — язык заголовков |

## Отличия от Lisp-режима

* Запись — инфиксная, `f(x)` вместо `(f x)`; индексы с 1 (в Lisp `tref` — с 0).
* Присваивания и функции языка не создают Lisp-переменных и не затирают библиотеку.
* Элементарные функции от точных чисел — символьные (`sin(5)`), а не float.
* `e` — число Эйлера, `i` — обычное имя; мнимая единица — `%i`/`ⅈ`.
* `diff(e, x)` — выражение первым; `integrate`, `limit`, `series`, `solve` — как в Lisp.
* Ошибки печатаются одной строкой без стека Lisp (`:debug` возвращает стек).
* Вывод — в синтаксисе языка и снова читается парсером: `true`/`false`, `∞`, `[ ]`, `{ }`.
* Из языка можно вызвать почти любую **экспортированную** Lisp-функцию библиотеки по имени (приватные имена модулей — `модуль::имя` — языку не видны, см. `docs\lisp-modules.md`); из Lisp язык доступен как `(math-eval "строка")`, `(math-eval-tree ast)`, `(load-math "файл.mth")`; `(math-read-program "строка")` возвращает AST, `(math-show значение)` — запись в синтаксисе языка.

## Из других программ

JSON-интерфейс (`dotnet run --project src/Lisp.Host -- --json`, одна строка JSON на запрос):

```
{"op":"math","code":"f(x) := x^2; f(3)"}
→ {"status":"answer","result":"...","pretty":"f(x) := x^2\n9", ... ,"ok":true, ...}
```

`pretty` — значения всех операторов в синтаксисе языка (по строке на оператор), `result` — те же значения в виде S-выражений, `output` — всё, что напечатал `print` (строки через `\n`; пустая строка, если `print` не вызывался). Переменные и функции языка живут в сессии процесса и доступны следующим запросам. Ошибка — `{"ok":false,"error":"сообщение","stack":[],"output":"..."}` без стека Lisp (`output` — то, что успело напечататься до ошибки).

**Формат ответа (шаг 22.1, `ToolResponse`; тот же будет у MCP-сервера).** Поля всегда присутствуют и идут в одном порядке; пустое — `null`:

```
{"op":"math","code":"solve([a*x^2 = 1, y - x = b], [x, y])","steps":"brief"}
→ {"status":"answer","result":"{[(= x ...) ...]}","pretty":"{[x = -sqrt(4a)/(2a), y = b - sqrt(4a)/(2a)], ...}",
   "note":null,"conditions":[{"condition":"a ≠ 0","sexpr":"(/= a 0)","reason":"solve: ответ для общих значений параметров (множитель старшего коэффициента или знаменателя)"}],"assumptions":null,"certificate":null,
   "steps":[{"rule":"polynomial-system","title":"Нелинейная система: метод базисов Грёбнера","comment":"...","before":"(list ...)",
             "before_pretty":"[-1 + a*x^2, -b - x + y]","after":"...","after_pretty":"...","level":"main","children":[]}],
   "warnings":null,"output":"","timing":{"ms":53,"timeout":false},"ok":true,"error":null,"stack":null}
```

| Поле | Что |
|---|---|
| `status` | исход по последнему оператору: `answer`; `unknown` — «не знаю» (невычисленная форма `integrate`/`limit`/`sum`/`product` или ошибка «…: не умею …»); `no-solution` — доказано, что решений нет (пустое множество из `solve`); `nonelementary` — `integrate`: алгоритм Риша доказал, что элементарной первообразной нет (шаг 21k.4–21k.6); `error`; `timeout` — зарезервирован |
| `result`, `pretty` | S-выражения и запись языка (при исключении — `null`) |
| `note` | короткая причина для `unknown` / `no-solution` (по-русски) |
| `conditions` | явные условия применимости ответа (канал `record-condition`, всегда включён, не зависит от `steps`; канал очищается в начале каждого запроса): массив `{"condition":"a ≠ 0","sexpr":"(/= a 0)","reason":"solve: …"}` — запись языка, S-выражение (каноническая форма `(/= c 0)`, `(> c 0)`), причина; дубликаты не повторяются; `null` — условий нет. Пишут `solve` (деление на нечисловой коэффициент или множитель, общие значения параметров в системах) и `integrate` (параметр считается положительным); у других операций пустое поле не означает отсутствия неявных допущений |
| `assumptions` | действующие декларации доменов сессии: `["x ∈ ℝ", "y ∈ (0, 1)"]` |
| `certificate` | проверка ответа (шаг 22.6): `null`, если не запрошена; по запросу `"certificate":true` (по умолчанию `false`; у операций `integrate`, `solve`, `simplify`, `expand`, `factor`, `together`, `apart`, `groebner`, `equivalent`, остальные дают `kind: "none"`) — объект `{"kind","verified","method","detail"}`. `kind`: `derivative` (интеграл: `d/dx F − f = 0`; определённый — ещё `F(b) − F(a)` = ответ), `substitution` (solve: решение подставлено в каждое уравнение), `equivalence` (исходное и ответ эквивалентны, механизм `equivalent`), `counterexample` (`equivalent` → `false`: точка и значения), `ideal_membership` (groebner: остаток каждого исходного многочлена по базису = 0), `none` (проверка не предусмотрена — `diff`, `limit`, `series`, `math`, `eval`). `verified`: `true` / `false` (булевы), строки `"numeric"` (только численно), `"partial"` (часть решений, `root-of`, не проверена), `"skipped"` (проверить нечем, причина в `detail.reason`), `"timeout"` (проверка не уложилась во время вызова; ответ при этом сохранён). `method` — чем проверено; `detail` — объект с выражениями (`derivative`, `residual`, `solutions[].residuals`, `remainders`, `counterexample.point`, …). Сертификат статус не меняет; при `verified: false` в `warnings` добавляется «ответ не прошёл проверку» |
| `steps` | пошаговое решение (шаг S.1) по запросу `"steps"`: `"brief"` — главные шаги верхнего уровня, `"full"` — всё дерево (глубина ≤ 4, ≤ 200 шагов), `"trace"` — плюс шаги упрощателя (`simplify:имя`, `detail`). Шаг — `{"rule","title","comment","before","before_pretty","after","after_pretty","level","children"}` (+ `"omitted": N`, если N вложенных шагов скрыто обрезкой; об обрезке — строка в `warnings`): `rule` — стабильный английский идентификатор приёма, `title`/`comment` — по-русски, `level` — `main`/`detail`, `children` — вложенные шаги. `[]` — запрошены, но не записаны; `null` — не запрашивались. См. «Пошаговые решения» |
| `warnings` | например, «результат содержит невычисленную форму integrate(...)» (частичный ответ) |
| `timing` | `{"ms": время запроса, "timeout": false}` |
| `ok`, `error`, `stack` | прежние поля: `ok` — запрос выполнен без исключения (у ошибки «не умею» `status` = `unknown`, а `ok` = `false`) |

**Шаг 22.3.** Операции `simplify`, `expand`, `factor`, `diff` (`order`), `integrate` (`from`/`to` — определённый), `solve` (`code` — уравнение или вектор уравнений, `var` — неизвестная или вектор), `limit`, `series` принимают `"syntax":"math"` — тогда `code`, `var` и границы записаны на математическом языке и операция выполняется как вызов языка (`{"op":"solve","code":"x^2 = 4","var":"x","syntax":"math"}`); по умолчанию `"syntax":"lisp"` — S-выражения, как раньше. MCP-сервер (`Lisp.exe --mcp`, те же ответы) — `docs/mcp.md`.

Кириллица и математические символы в ответе не экранируются (`"x ∈ ℝ"`, а не `"x ∈ ℝ"`, как до шага 22.1; для JSON-разборщика это одно и то же).

## Известные ограничения

* Переменные ленивые только на уровне значений: `y := x^2` с уже присвоенным `x` вычислит `x^2` сразу (при присваивании правая часть вычисляется); пересчёт при использовании касается имён, не имевших значения в момент присваивания. Локальные переменные (параметры) не пересчитываются.
* Невычисленные формы (`integrate(...)`, `limit(...)`, `sum(...)`, `if(...)`), сохранённые в переменной, пересчитываются при использовании только для `if`, отношений, индексов и `sum`/`product`.
* Скорость (Шаг 21b): язык компилируется в замыкания, `loop` — порядка 700 тысяч итераций в секунду над глобальными переменными (10^5 итераций — ≈ 0.15 с), вызов функции языка — порядка 1–2 мкс (fib(20) — ≈ 20 мс), `v[i] := e` — O(1) для вектора, принадлежащего переменной. Лимит по умолчанию (миллион итераций) достигается за секунды. Первый запуск в процессе медленнее (JIT, ≈ 2–3×). Определение функции и каждый оператор верхнего уровня компилируются при выполнении (≈ 0.1–0.3 мс на оператор); определение или `clear` функции с именем итератора (`sum`, `vector`, ...) перекомпилирует все функции.
* Если условие `if` внутри `loop` неопределённо (например, символьная переменная), `if` остаётся невычисленным, и цикл упирается в лимит итераций.
* Переменная итератора (`k` в `sum`/`vector`/`select`/`iterate`) затеняет глобальную и не проверяется на присвоенность (в отличие от `solve`, `integrate`, ...).
* Присваивание строки/подматрицы (`m[1] := [7, 8]`) и вложенных индексов (`m[1][2] := 0`) не поддерживается.
* `and`/`or` останавливаются на первом определённом операнде, но неопределённые операнды вычисляются все.
* Определения с условиями (`f(x) := ... ` по ветвям с образцами) не поддерживаются.
* Интервалы: см. раздел «Интервалы»; границы должны быть числами (или ±∞) — символьные границы `(0, a)` — ошибка; закрытый интервал `[a, b]` вне позиции домена нужно писать `interval(a, b)`.
* Множество решений `solve` упорядочено по внутреннему порядку выражений: `{2^(1/2), -2^(1/2)}`, а не по возрастанию значений.
* `taylor(e, x, a, n)` даёт члены степени `< n` (а не `≤ n`, как в Derive).
* Декларации (`:∈`) — состояние сессии: `clear()` и `math-reset` снимают их все (кроме системной `pi > 0`), `x :∈` без домена и `undeclare(x)` — декларации одного имени; `declarations()` — список текущих.
* `sin(1)`, `sin(π/5)` (нерациональные кратные π и знаменатели 5, 7, 12, …) остаются формами; числа свыше 10^12 под корнем не раскладываются на множители.
* `return` в хвосте функции или в операторе тела `loop` (в том числе в ветвях `if`/`prog`) и `exit` в операторе тела `loop` — обычные ветвления; в остальных позициях (`return` внутри цикла, в аргументе вызова, в теле итератора) — через исключение: функция выполняется под перехватом (≈ 10–30 мкс на выход), хвостовая рекурсия в ней не оптимизируется.
* Хвостовые вызовы функций языка не растут по стеку (`cnt(n, a := 0) := if(n = 0, a, cnt(n - 1, a + 1))` работает при `n` = миллион); нехвостовая рекурсия ограничена логической глубиной Lisp (порядка девяноста тысяч вложенных вызовов: `cnt(60000)` работает, `cnt(100000)` — ошибка «Превышена глубина рекурсии»).
* Голое имя `exit` (без скобок) в операторе тела `loop` всегда выход из цикла, даже если переменной `exit` присвоено значение.
## piecewise: кусочно-заданные выражения

`piecewise((условие1, выражение1), (условие2, выражение2), …)` читается в Lisp-форму
`(piecewise ((условие1 выражение1) …))` и печатается обратно; ветви берутся как записаны (не вычисляются),
условия — отношения `=`, `≠`, `<`, `>`, `≤`, `≥` и `and`/`or`. Так печатаются ответы `integrate` с параметрами:
`integrate(exp(a*x), x)` → `piecewise((a ≠ 0, exp(a*x)/a), (a = 0, x))`. `diff` дифференцирует по ветвям;
слияние/упрощение ветвей не выполняется.

| Функция | Что делает |
|---|---|
| `piecewise((условие1, выражение1), ...)` | кусочно-заданное выражение: первая пара с верным условием |
